# runbook v3：日志证据通道、fresh 目录负例、REF 字面量、Caddy 拆分

## 背景

用户实测 PR runbook 提三缺陷：①SELinux 负例 15s 时 fetching/0 denial，与期望不符；
②Quadlet 测试假设测试机有 repo；③Caddy 应 agent 自签自测、WAN 侧通知管理员协同。
讨论中用户以 godoword 同宿主历史实测（fresh 目录无 :Z 首写即 os error 13）反证宿主会拒绝，
推翻我"宿主不拒绝"的误判；真因指向**负例复用正例目录被 :Z 私有 MCS 类别污染**
（mkdir recursive 对已存在目录 no-op，跳过首写；跨类别读写产生迷惑中间态）。

## 决策

runbook v3：负例证据通道 = `podman logs` 终态标记（fetch error/done/cache hit），
等待窗口从代码首写时序推导（mkdir 先于下载 → 秒级）+ 启动竞态余量 ≤30s；
**负例独立 fresh 目录**；不可判定（label 关闭宿主）记 SKIP+证据；砍掉 readyz 轮询/AVC/ls -Zd 主证据。
Quadlet/Caddyfile 产物 curl raw 投递，**REF 字面量内联命令**（799a2884…，产物变更同批更新）。
Caddy 路由策略/TLS 终止进 smoke T8 自动化（自签 tls internal），人工残留收窄 WAN 暴露面，
管理员精确命令+期望+清理、agent 判读协同。conventions 纪律同步（grounding/终态/首写时序/fresh 隔离/REF）。

## 后果

负例简单且可执行；期望输出有 godoword 实测 grounding；待用户 fresh 目录复跑确认污染假设
（若仍不拒绝按缺陷重议）。见 [runbook](../wiki/deploy/acceptance-runbook.md)、
[conventions](../docs/project/conventions.md#人工残留-runbook-纪律)。
